# Product Vision PRD

## Working title

Nixfred AI Systems Workbench

## Product promise

Practical instruments for understanding and building reliable AI systems.

## Audience

- Architects explaining AI systems to customers or teams
- Builders making design decisions before writing code
- Operators diagnosing production behavior
- Curious technical users learning by manipulating a system

## Principles

1. Every page must let the user do something.
2. Inputs must produce an inspectable result, not generic prose.
3. Assumptions must be visible and editable.
4. Results should be exportable or shareable where useful.
5. Tools should teach through use without becoming textbook chapters.
6. The visual language should feel like one Nixfred laboratory.
7. A tool must work with sample data and should not require an API key for its core experience.
8. No user input leaves the browser unless the interface explicitly says so.

## Product boundaries

Included:

- Interactive calculators, designers, simulators, evaluators, and diagnostic aids
- Educational explanation embedded directly in results
- Local persistence and portable project data

Excluded:

- General AI chat
- News, trend feeds, essays, or speculative “dead internet” material
- A full production agent runtime
- Account management, billing, or team collaboration in the first release
- Hidden claims that a simulated result is a real model benchmark

## Success signals

- A first-time visitor can identify a useful tool within 20 seconds.
- Every released tool has a complete sample workflow.
- A user can move between tools without relearning the interface.
- Adding a tool requires a registry entry and its isolated route, not a landing-page rewrite.
- An incomplete tool can be hidden without breaking the site.
